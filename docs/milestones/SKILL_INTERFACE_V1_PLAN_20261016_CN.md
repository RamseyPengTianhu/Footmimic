# 统一技能接口 v1 与三条技能线计划

日期：2026-10-16

状态：当前接口与技能线计划。取代[主计划](SOCCER_SKILLS_RESEARCH_PLAN_20261014_CN.md)中的"latent 架构接口 v0"（5 维接触时钟）
和 P3 的"统一接口"草案；主计划的目标、硬约束、P0 结果、资产清单和工作规则继续有效。

适用范围：主线的射门、传球，支线（`dribble-clean-v0`，另一台服务器）的盘带。三条线用同一套观测、同一个网络模块、
同一套奖励模板，技能之间只差"规划层给出什么样的触球事件序列"。

## 0. 相对 v0 的四处修改

| v0 | v1 | 原因 |
| --- | --- | --- |
| 接触时钟：距下次触球的时间（帧级） | 事件驱动的软相位：阶段由球与脚的几何关系和实测触球切换，不数帧 | 真机上球位、滚动和步伐都有误差，精确的触球时刻给不出来 |
| 触球面：内/外两类 | 触球事件：脚、G1 脚板区域、球上触点高度、出球目标 | 盘带、传球、射门的脚法用同一种描述 |
| 命令：出球速度向量 | 出球目标点 + 模式（到达 / 全力） | 速度不出现在任何命令里；传球和盘带的力度由目标距离决定，射门恒为全力 |
| 球观测始终输入 | 控球标志门控球观测 | 射门、传球放球后，球不应再影响机器人；盘带始终控球 |

## 1. 物理前提（2026-10-16 核对）

**G1 的脚是一块平板。** 训练用 URDF（`source/whole_body_tracking/soccer/assets/unitree_description/urdf/g1/main.urdf`）和
MuJoCo 模型中，`*_ankle_roll_link` 的碰撞体只有 7 根细圆柱拼成的脚底板：长约 0.19 m（脚跟 −0.054 到脚尖 0.132），宽约 0.07 m，
厚约 2 cm，位于踝关节下 2.5 cm。没有脚趾关节；踝只有 pitch、roll 两个自由度；脚面没有碰撞体。

由此：

- 能区分的触球部位只有脚板的几个区域（见 2.1）。人类脚法名只作为标签映射到这些区域，不直接进入观测。
- **脚面（正脚背）没有碰撞体。** 真机的脚并不只是一块板：外壳网格（`meshes/g1/right_ankle_roll_link.STL`）在中足处高到踝关节上方
  2.4 cm，只是没有建碰撞。S0（第 4 节）显示，现在 8 m/s 的射门里，本该由脚面和踝外壳接触的位置，在仿真里由脚板前端加小腿碰撞圆柱
  （`*_knee_link`）代替。用户确认真机踝关节可以承受触球，必要时加护垫（2026-10-16），因此决定加脚面碰撞体，见 4 节 S0b。
- **弧线球做不出来。** Isaac 和 MuJoCo 都没有马格努斯力，球旋转也不拐弯。"兜射"只能保留"内脚背、球心偏下"的触球方式，不评弧线。
  挑球（球离地）有物理意义，可以做。
- 球的滚动阻力：Isaac 原本几乎不减速。分支已按"水平恒定减速度 0.49 m/s²、速度层面施加"实现（`mdp/ball_physics.py`），
  主线和 MuJoCo 部署链路要同步实现，这是传球和盘带"按距离定力度"的前提。

## 2. 接口 v1

### 2.1 触球事件

每一次触球用一个事件描述，三种技能通用：

| 字段 | 编码 | 维度 | 说明 |
| --- | --- | ---: | --- |
| 脚 | 右 = 1，左 = 0 | 1 | |
| 脚板区域 | one-hot：前端、前内角、内侧、前外角、外侧、脚面、脚底；全 0 = 不指定 | 7 | 数据没有标注时用"不指定"；脚面 = 脚板前部的上表面把球托起或推出 |
| 球上触点高度 | −1 球心以下、0 球心、+1 球心以上 | 1 | −1 用于挑球、兜射；+1 用于压球、踩球 |
| 出球目标 | 目标点相对球的位置，朝向坐标系 xy（米，按 0.1 缩放） | 2 | 传球 = 队友；盘带 = 下次触球时球该在的位置；射门 = 球门 |
| 出球模式 | 到达 = 0，全力 = 1 | 1 | 射门恒为 1；传球、盘带为 0 |
| 离地 | 地滚 = 0，离地 = 1 | 1 | 第一版恒为 0 |

人类脚法到事件的映射（只是标签，便于命令和数据整理）：

| 技能 | 脚法 | 脚板区域 | 触点高度 | 模式 |
| --- | --- | --- | ---: | --- |
| 盘带 | 正脚背/脚弓向前推 | 前端 / 内侧 | 0 | 到达 |
| 盘带 | 内脚背扣球 | 前内角 | 0 | 到达 |
| 盘带 | 外脚背拨球 | 外侧 / 前外角 | 0 | 到达 |
| 盘带 | 油炸丸子 | 内侧，左右各一个事件，间隔约 0.2–0.3 s | 0 | 到达 |
| 盘带 | 踩球、拉球 | 脚底 | +1 | 到达 |
| 射门 | 内脚背抽射 | 前内角 | 0 | 全力 |
| 射门 | 正脚背抽射 | 脚面 | −1 到 0 | 全力 |
| 射门 | 内脚背兜射 | 前内角 | −1 | 全力（不评弧线） |
| 射门 | 外脚背射门 | 前外角 | 0 | 全力 |
| 射门 | 脚尖捅射 | 前端 | 0 | 全力 |
| 射门 | 脚弓推射 | 内侧 | 0 | 全力（预期球速较低） |
| 传球 | 脚弓传球 | 内侧 | 0 | 到达 |
| 传球 | 正脚背平抽 | 脚面 | 0 | 到达，目标远 |
| 传球 | 内脚背长传 | 前内角 | −1 | 到达，离地（后期） |
| 传球 | 脚尖挑传 | 前端 | −1 | 到达，离地（后期） |

**脚踝不单独编码。** 脚板区域加出球方向基本决定了触球瞬间的脚踝姿态：该区域的法向应对准出球方向。由奖励约束（2.6），
脚踝怎么动由策略学。参考数据里的脚踝也不用视频去"精修"，原因和替代做法见 2.8。

### 2.2 软相位（取代帧级接触时钟）

| 字段 | 编码 | 维度 |
| --- | --- | ---: |
| 阶段 | one-hot：接近、触球、随球 | 3 |
| 接近进度 | 1 − 球到触球区域的距离 / 本事件开始时的距离，截断到 [0, 1] | 1 |

- 阶段切换由事件驱动，不由时钟驱动。"接近"切到"触球"的条件是球进入该脚可及范围；"触球"切到"随球"的条件是检测到触球
  （仿真用接触传感器，真机用视觉测到的球速突变）。
- 盘带的节奏不用秒表示：规划层把下一次的出球目标放在"约 N 步后还能够到"的位置，步态节奏由 z 和人体数据给出。
- 训练时对阶段切换加扰动（提前或推迟 0.2–0.3 s），迫使策略用球的观测来对准时机。
- `kick_frame` 和 Contact Graph 仍然是核心：它们在参考数据里标出"哪一段是接近、哪一帧触球、用哪只脚哪个面"，
  用于生成训练时的事件序列和奖励窗口。只是不再把帧号当真值喂给策略。

### 2.3 两层目标与规划层

| 层 | 内容 | 来源 |
| --- | --- | --- |
| 任务目标 | 盘带：目的地或方向加速度档；传球：队友位置加类型；射门：球门位置加技巧 | 用户命令 |
| 事件目标 | 当前事件和下一事件（2.1 的字段） | 规划层按任务目标计算，每次触球后重算 |

规划层第一版是规则，不学习：

- 射门：一个事件，模式全力，目标为球门；技巧决定脚板区域和触点高度。
- 传球：一个事件，模式到达，目标为队友；类型决定区域、触点高度和离地。
- 盘带：事件链，"传给未来的自己"。每次触球后按球的实际位置和身体速度命令，把下一事件的目标放在前方可及处，
  区域按变向需要选（直走用前端或内侧，向内变向用前内角扣，向外用外侧拨）。球偏了下一次修正，天然闭环。
- 切换：盘带事件链的最后一个换成传球或射门事件，就是"带球后传球/射门"。

### 2.4 控球标志与球观测

- 控球标志 p：还有待执行的触球事件时为 1；放球后没有下一个事件时为 0。盘带全程为 1；射门、传球在触球后进入"随球"阶段时转为 0。
- 球观测 = p × [骨盆系球位置 xyz、骨盆系球速度 xyz、球相对当前事件脚板区域中心的位置 xyz]，外加 p 本身。
  p = 0 时球观测全部为 0，机器人进入恢复、站立或执行下一个命令。
- 这取代主线 e1d378259 中"恢复阶段用虚拟球观测"的推理时补丁：门控在训练时就存在，不再有分布外问题。

### 2.7 标签来源：仿真事后测量

脚板区域、触点高度和实际出球结果都不从视频里精确标注，而是在仿真里测：

- 参考数据：用已有 tracker 回放（射门用 s859，盘带用分支的 Stage 1 或 Stage 2′ 产物），记录每次触球的实际区域、法向和出球结果，
  作为该 clip 的事件标签。视频和参考动作只负责提供动作风格的覆盖。
- 监督阶段（蒸馏、Stage 1′）可以做事后重标注：rollout 实际打出的结果当作它的事件目标，补充训练样本。PPO 阶段直接用 2.6 的奖励。
- 盘带数据已有的 `dribble_cg_surface`：0 = 内侧、1 = 外侧（两条 clip 的触球序列分别为 O-O-I-I 循环与 I-O 交替，已核对），
  `dribble_cg_foot` 1 = 右脚。这两项直接转成事件的脚和区域。

### 2.8 脚踝：用接触几何修正，不用视频精修

脚法的完整方案（规格卡、触球感知的参考修正、脚法奖励、教师与步骤）见[脚法学习计划](FOOT_TECHNIQUE_PLAN_20261016_CN.md)，本节只是摘要。

用户提出过用更精细的脚踝视频数据替换全身动作里的脚踝。建议不这样做：
- 视频里脚踝最不可靠：触球瞬间脚速 15–20 m/s，运动模糊、遮挡严重；人脚还有脚趾和距下关节，映射到 G1 只有 pitch、roll 的平板脚时本身就有歧义。
- 现有 tracker 在触球附近已经动态屏蔽脚踝的跟踪（dynamic ankle masking），触球瞬间的脚踝本来就由 RL 决定，不由参考决定。
- S0 显示触球区域由参考的整体动作风格决定，而且很稳定（同一条参考 5 个 seed 基本落在同一区域），技术差异主要来自髋和腿的朝向，而不是脚踝曲线。

替代做法：
1. **接触几何修正参考。** 在参考的触球窗口内，按事件的脚板区域和出球方向，用 2 自由度的解析逆运动学求脚踝 pitch、roll，
   使该区域法向对准出球方向，前后平滑过渡回原参考。这样触球那一刻的脚踝是精确的，其余时间沿用数据。
2. **奖励约束**（2.6 的区域与法向对齐两项）保证策略真正用对区域。
3. **视频只用于粗标注**：需要时用带脚部关键点（大脚趾、小脚趾、脚跟）的人体姿态模型，从比赛视频里判断"用哪个区域触球"，
   作为事件标签的补充，不提取角度曲线。

## 5. 主线：传球（P）

## 7. 合并（原 P3）

- 一个共享 latent tracker：射门、传球、盘带的数据和事件一起训练（或从各自产物蒸馏），观测完全一致，只有规划层分技能。
