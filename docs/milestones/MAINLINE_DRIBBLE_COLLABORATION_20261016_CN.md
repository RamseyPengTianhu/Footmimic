# 主线与盘带支线的协作计划

日期：2026-10-16

## 1. 定位

| | 主线 | 盘带支线 |
| --- | --- | --- |
| 研究内容 | 射门与传球的脚法：[脚法学习计划](FOOT_TECHNIQUE_PLAN_20261016_CN.md)（S0b → T0–T4 → S1） | 盘带：[接口 v1](SKILL_INTERFACE_V1_PLAN_20261016_CN.md) 第 6 节（D-a → D-e） |
| 位置 | 本机（hrl-5090-server），`main`；共享代码发布在分支 `skill-interface-v1` | 另一台服务器（teambruce@192.168.1.42），分支 `dribble-clean-v0` |
| 职责 | 定研究方向与门槛；维护共享接口和共享资产；最终合并 | 在共享接口上实现盘带；提供盘带的规格卡数值、奖励、数据和结果 |
| 算力 | 本机只用 cuda:0 | 支线服务器 |

两条线用同一套接口、同一个网络、同一套脚法规格与奖励，区别只在规划层给出的事件序列。目标是合并时只需把盘带的环境和规格卡接进来，
不需要改网络或观测。

## 2. 所有权

**共享件（只由主线修改，支线按版本取用）：**

| 共享件 | 位置 | 状态 |
| --- | --- | --- |
| 网络 | `source/whole_body_tracking/soccer/latent/latent_skill_net.py` | 已完成 |
| 观测与事件编码、软相位、球观测门控、区域分类、规划层工具 | `source/whole_body_tracking/soccer/latent/skill_event.py` | 已完成 |
| 共享测试 | `scripts/rsl_rl/test_skill_interface.py` | 已完成，12 项 |
| 脚法规格卡的格式与射门、传球的卡 | 脚法学习计划第 1 节 | 草案，T0 后冻结 |
| 机器人资产（加脚面碰撞体后的 URDF 与 MJCF） | 主线 S0b 产出 | 待做 |
| 脚法奖励与触点测量（Isaac 版） | 主线 T2 产出 | 待做 |
| 触球感知的参考修正工具（腿部逆运动学） | 主线 T1 产出 | 待做 |
| MuJoCo 中球的滚动阻力 | 主线 | 待做 |

**支线自有（主线只读，合并时并入）：**
- 盘带环境、课程、盘带专属奖励（`dribbling_ball_front_zone`、`dribbling_ball_velocity_follow` 等）。
- 盘带规格卡的数值（推、扣、拨、踩）：格式用主线的，数值由支线按数据校准。
- 盘带数据的标注与接地处理。
- Isaac 中球的滚动阻力 `mdp/ball_physics.py`（已完成；主线将直接采用，作为共享件的 Isaac 版）。

**规则：** 共享件不 fork。支线需要改接口时提需求（写在 `DRIBBLE_HANDOFF.md` 的"接口需求"小节），主线改代码、补测试、升版本号，
支线再取新版本。支线对共享件的本地临时补丁必须在交接文档里列出，合并前清零。

## 3. 双向流动

| 方向 | 内容 | 方式 |
| --- | --- | --- |
| 主线 → 支线 | 共享代码、共享资产、计划文档 | 分支 `skill-interface-v1`；支线用 `git checkout origin/skill-interface-v1 -- <路径>` 取文件 |
| 主线 → 支线 | 数据（站立 `s830`、行走 `s861` 已送达） | 从本机 `rsync -aL` 到支线服务器 |
| 支线 → 主线 | 进度、run、checkpoint、门槛数值、失败现象、接口需求 | 支线在 `dribble-clean-v0` 提交并更新 `DRIBBLE_HANDOFF.md`；主线 `git fetch` 只读，汇总到主计划 P2 节 |
| 支线 → 主线 | 可复用的代码（球的阻力、盘带奖励） | 主线读取后并入共享件或合并时并入 |

推送、启动正式训练都需要用户在对应一侧明确同意。两边的 Claude 会话之间不直接通信，消息由用户转达。

## 4. 同步点

| 同步点 | 触发条件 | 内容 |
| --- | --- | --- |
| 0 起步（现在） | `skill-interface-v1` 推送 | 支线取共享模块，用两条盘带参考 + 站立 + 行走做 D-a 冒烟；主线做 S0b、T0 |
| 1 接口冻结 | 主线 S0b 完成且支线 D-a 跑通 | 冻结观测维度、区域集合、机器人资产（含脚面碰撞体）；版本 v1.0；支线换用新资产 |
| 2 奖励共享 | 主线 T2 完成 | 支线在盘带中接入区域命中、法向、违规接触等脚法奖励；盘带规格卡数值由支线给出 |
| 3 先验模式 | 主线 S1 结论 | 先验模式通过：支线 Stage 2′ 切换到先验模式；不通过：两边都暂停在后验模式，主线先查原因 |
| 4 合并 | 支线 D-c 通过，且主线 T3、S1 通过 | 合并代码到 `main`；用射门、传球、盘带的全部数据训练一个共享 latent tracker；验收"站立 → 盘带 5 m → 射门/传球" |

支线在同步点之间不需要等主线：D-a、D-b 只依赖已发布的共享模块；D-c 在拿到共享的脚法奖励之前，先用支线已有的触球判定和内外侧标签。

## 5. 决策权

| 事项 | 谁决定 |
| --- | --- |
| 启动正式训练、推送、接口冻结、真机相关 | 用户 |
| 研究方向、各步骤门槛、共享件的修改 | 主线 |
| 盘带环境、课程、奖励权重、盘带规格卡数值 | 支线（需在交接文档里记录理由） |
| 门槛没过时的去留 | 主线提出，用户拍板 |

## 6. 风险

- **资产分叉：** 两边机器人碰撞体不一致会让脚法奖励和结果不可比。同步点 1 之后只允许用共享资产。
- **球的物理不一致：** Isaac 用支线的速度层阻力；MuJoCo 由主线补齐。两边都以"水平恒定减速度 0.49 m/s²"为准。
- **代码冲突：** 两边都改过 `commands_multi_motion_soccer.py` 和奖励文件。新代码尽量放在新文件里，不改共用的旧文件。
- **支线空等：** 每个同步点都写明了支线可以独立推进的部分（第 4 节最后一段）。
